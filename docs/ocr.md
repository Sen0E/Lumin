# OCR 引擎与设置维护

适用 Lumin 0.11.0。生产识别全部通过插件，宿主不查找或执行系统 Tesseract。

## 设置归属

- 偏好设置不再单独提供「文字识别」页，OCR 设置统一位于服务设置。
- 「服务设置 → OCR 服务」：列出已安装且声明 recognize 的插件，选择后载入默认参数，编辑/测试当前草稿，保存后用于新任务。没有当前平台入口的插件不可选。
- 「停用 OCR」：清除草稿引用、记录主动停用，保存后生效。此选择重启保持，启动不会自动开启。
- 没有配置引擎时，图片/截图识字与截图翻译均在获取图片之前提示并打开「服务设置 → OCR 服务」。缺失或损坏的插件通过原插件调用链报告错误。

## 随包默认引擎

发布构建命令：

```bash
scripts/build-release.sh linux/amd64
scripts/build-release.sh windows/amd64
```

脚本先运行现有 PP-OCRv6 tiny 构建脚本，准备 `resources/<platform>/bundled-ocr.luminext` 后执行 MyGo build。固定模型、字典、运行库及来源校验由插件构建脚本维护。平台资源文件是生成物，不入版本控制；直接执行 MyGo build 前须自行准备资源。Windows 便携包必须包含 EXE、图标以及 bundled-ocr.luminext，不能只分发 EXE。

启动成功获得单实例锁后，`ocrsetup.Ensure` 执行以下操作：

1. 主动停用和其他已有引擎选择直接保留；历史 `example.tesseract@1.0.0` 按待迁移处理。
2. 查找已安装的 `lumin.ppocrv6-tiny@1.0.0`；没有则校验随包资源 ID、能力、平台，再安装，不执行插件。
3. 保存默认引擎和线程/最长边参数；保存失败保留旧配置并显示初始化提示。

没有资源时不下载、不启用系统回退，允许手动安装插件。macOS/ARM 尚无随包默认引擎。移除当前引擎需先停用并保存，再卸载；正在执行识别或诊断时阻止卸载。

## 诊断与性能

测试使用嵌入的公开英文图片，内容为 `Lumin translation test.`；临时文件 0600，结束后清理。使用当前草稿的完整参数，显示实际返回文本与耗时，超时 30 秒；云插件会收到该固定图片，界面已明确告知。无需发送当前截图或剪贴板。测试不写配置和历史、不改变翻译输入及识别结果。

测试持有独立 generation 和 cancel。切换引擎、取消、放弃修改、保存、恢复数据和退出使旧测试失效；直接编辑参数后旧结果标为需要重测。后台只读取深拷贝配置，写回通过 Window.Update。

当前插件协议仍是一次请求启动一个进程，识别完释放运行库/模型；本轮未引入进程常驻或跨请求模型缓存。长期缓存需要后续独立协议与生命周期设计，以实测瓶颈决定是否实施。默认离线识别无需用户额外安装工具，但 Linux 仍使用标准系统运行库和现有桌面截图接口。

## 兼容性

配置仍为 version 1：新增 `ocr_disabled,omitempty`，旧配置缺失为 false。旧 `ocr_languages` 可读取且透传给旧插件，新配置默认空，已无非空校验；新插件的语言等参数应通过自己的 settings 声明。PP-OCRv6 tiny 依靠模型字典识别，忽略 Tesseract 风格语言字段。

除历史 `example.tesseract@1.0.0` 外，已有明确引擎引用不会自动切换版本。该旧示例在有随包引擎时迁移为默认离线插件，重置旧参数；无资源则保留原配置并允许手动换引擎。首次自动配置可将旧版未选择插件的用户改为随包离线引擎；没有随包资源的源码构建需要手动安装。备份、恢复会保留主动停用状态。

## 回归

`ocrsetup/setup_test.go` 覆盖首次注册、持久化、安装时不执行入口、既有选择/主动停用保留及缺少资源。`desktop/ocr_settings_test.go` 覆盖无系统回退、配置导航、参数多帧编辑、停用/放弃、固定图片、结果隔离、临时文件清理、取消旧结果与真实插件测试。通过 `LUMIN_PPOCR_PACKAGE` 指定真实插件包可执行离线模型集成测试。
