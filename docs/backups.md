# 配置与历史备份维护

适用 Lumin 0.7.0；主窗口「备份设置」。

## 用户操作

1. 导出备份：保存 `.luminbackup` 文件，内容为已保存的配置、历史和收藏。未保存草稿、插件程序、环境变量值、窗口位置和 OCR 图片不在备份中。
2. 默认不勾选密钥：移除 API Key、HTTP 令牌、接口 URL 中的认证/查询/片段及全部插件参数；禁用翻译服务和 HTTP。保留环境变量名称。恢复后重新填写参数再启用。原文和译文仍包含在文件中。
3. 勾选「包含密钥和插件参数」导出完整明文配置。恢复前自动生成的本机备份也包含这些内容。
4. 选择备份并预览：只校验并展示文件名、版本、时间、历史/收藏/服务数量和凭据范围，不修改当前数据。
5. 勾选覆盖确认后恢复：覆盖已保存配置、全部历史与未保存草稿，不合并。已有任务取消，剪贴板监听关闭；快捷键重新注册，默认语言和 HTTP 服务配置重启生效。插件程序需要另行安装到当前平台；缺失或配置不完整的插件在使用时报告错误。
6. 恢复成功显示 `backups/before-restore-*.luminbackup` 路径。要撤回恢复，重新选择这个文件预览并恢复。自动备份不自动清理。

## 格式与边界

JSON 顶层：`format: "lumin-backup"`、`version: 1`、`created_at`、`includes_secrets`、`config`、`history`。配置沿用 version 1。导入最多 64 MiB / 50000 条历史；校验完整 JSON、未知字段、版本、配置、历史 ID 唯一性、时间、请求和结果条数。不接受 ZIP、第三方备份或嵌入路径，不解包、不自动安装或运行插件。

密钥范围标记用于预览及已知字段一致性校验；它不是任意原文/译文或用户自定义内容的秘密扫描器。默认导出保守移除整个插件参数映射，避免依赖插件自报的 secret 标志。

## 存储迁移与提交

- `state.json`（存储 version 1）包含 config 和 history，两个部分一次原子替换。每次提交先写同目录 0600 临时文件、同步文件、关闭并重命名；失败清理临时文件。Windows 权限由系统 ACL 决定。
- 无 state.json 时读旧 config.json/history.json；首次成功保存或恢复时写入快照，原文件保留。随后旧文件不再生效。不要用旧版应用继续写同一目录，否则新旧数据会分叉。
- 恢复时在同一存储锁内保存恢复前备份，再提交快照。恢复前备份失败或快照提交失败都不会替换当前数据。预览确认使用内存内容，文件之后变化不影响这次确认。
- 恢复成功递增存储 revision；旧翻译任务的 AddIfRevision 不写回。UI 取消任务和存储检查共同防止迟到结果。
- 测试覆盖进程内写入失败；未模拟断电、文件系统故障或 Windows 文件占用。文件同步与重命名的持久性仍依赖系统/文件系统。

## 损坏数据与手工恢复

损坏的 state.json 阻止加载和覆盖，不会偷偷回退旧文件。先完整退出并复制整个数据目录。若需使用自动备份恢复，可将损坏的 state.json 和旧 config.json/history.json 一并移至隔离目录，启动空数据实例，再在备份设置中导入完整恢复文件；确认正常前保留隔离文件和 plugins 目录。不得只删除 state.json 后依赖已过期的旧文件恢复新历史。

## 代码与测试

- `internal/backup`：格式、边界、凭据处理、导入导出。
- `internal/storage`：快照、旧数据迁移、恢复前备份、提交及 revision。
- `internal/desktop/backup.go`：导出/预览/确认状态与原生设置页。
- 回归包括损坏/超大/未知版本、重复记录、凭据默认去除、旧数据迁移、失败保留、恢复备份往返、迟到记录拒绝和 UI 预览不写入。
