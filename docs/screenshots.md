# 截图框选与 OCR

## 使用

从托盘选择「截图识字」或「截图翻译」。0.5.0 起翻译窗口不再放截图工具按钮。默认截图翻译快捷键为 `Ctrl+Alt+S`，macOS 为 `Cmd+Alt+S`。从 0.1.0 升级的已有配置若缺少 `screenshot_shortcut`，快捷键保持禁用，需在设置中填写并保存。

当前可见的配置、翻译和识别窗口暂时隐藏。应用在隐藏窗口前记录鼠标所在显示器，把它固定为本次截图目标，只获取该显示器的图像，随后在同一显示器打开原生全屏框选窗口。其他显示器不进入框选或 OCR。0.10.0 起，左键拖拽选中区域，松开后立即提交识别；右键或 Esc 取消。框选画布铺满无边框窗口，没有顶部工具栏；操作和尺寸提示直接绘制在画面上。误点、指针取消或小于 2×2 原图像素的选区不提交，可以直接重选；支持任意方向拖动。Enter 仅作为辅助确认当前有效选区的快捷键。

快照按比例显示在目标显示器内，可能出现留白。多屏虚拟桌面提供的整屏快照会按横排、竖排和负坐标位置裁剪出鼠标所在显示器，**只打开一个覆盖层，且不会覆盖其他显示器**。框选位置按归一化坐标映射回该显示器原图像素，裁剪使用原始分辨率；界面中的 px 表示实际裁剪尺寸。当前不支持选区拖动手柄、滚轮放大或跨多个窗口连续框选。

确认或取消后，只恢复截图前可见的窗口（不抢焦点），使用已保存的 OCR 引擎。截图识字成功后打开识别结果窗口，截图翻译则进入翻译窗口；从后台发起截图不会打开设置。取消截图保持原来的可见状态；获取或识别错误会在小窗口显示。截图识字将文字填入编辑器；截图翻译随后调用已启用翻译服务。没有服务时在小窗口提示，点击「配置翻译服务」才打开设置。屏幕图片不会作为翻译请求发送给普通文本翻译服务；若选择云端 OCR 插件，它可按自身实现上传选区图片。

当前一次只运行一个识别/翻译任务。已有任务忙碌时，新的截图动作忽略；可以先取消任务再截图。整个识别流程（包括系统权限与选区等待）上限 90 秒，超时会关闭框选窗口并按原可见状态恢复窗口。

## 平台获取方式

| 平台 | 实现 | 验证范围 |
| --- | --- | --- |
| Linux Wayland / X11 | XDG Desktop Portal Screenshot，通过会话 D-Bus 请求；`interactive=false` 后按鼠标显示器裁剪，并用 GTK `gtk_window_fullscreen_on_monitor` 定位框选层 | 用户已确认当前环境截图 OCR 可用；横排/竖排/负坐标裁剪有自动化测试，多屏和混合 DPI 待实机复验 |
| Linux 门户缺失 | 明确报告桌面接口不可用，无命令行工具回退 | 需要桌面集成提供 Screenshot 门户 |
| macOS 14+ | ScreenCaptureKit 获取固定 CGDisplayID 的图像，NSBitmapImageRep 在内存转换 | arm64 交叉编译通过；录屏授权、负坐标和 Retina 缩放待真机验证 |
| Windows | 进程内调用 Win32 GDI：GetMonitorInfo、CreateDIBSection、BitBlt，使用线程 DPI awareness | amd64 交叉编译通过；多屏和混合 DPI 待真机验证 |

Linux 需启动 `xdg-desktop-portal` 和匹配桌面的后端，且后端提供 Screenshot 接口。桌面可能弹出授权窗口，某些后端还会先让用户选择屏幕/区域；Lumin 对后端返回的图片继续框选。`interactive=false` 不代表绕过授权。门户拒绝、取消或接口不可用时直接返回，不查找其他截图工具。

全局快捷键的授权由 MyGo / 桌面门户处理，与截图权限是两条独立链路。快捷键不可用时可从界面或托盘截图。

macOS 需要给实际运行程序授予屏幕录制权限，截图接口要求 macOS 14 或以上。通过 SCShareableContent 找到固定显示器，再由 SCScreenshotManager 获取原始像素；目标无效时报告错误。Windows 使用固定 HMONITOR 读取物理屏幕边界；应用以同一显示器信息定位框选层。两者均不启动系统命令。

## 图片生命周期

系统快照解码前检查大小和像素数，上限 64 MiB / 6400 万像素。框选结果编码为权限 `0600` 的临时 PNG，交给 OCR 后清理，失败和取消也清理。Windows/macOS 的完整快照在内存处理，不产生完整截图临时文件。

门户返回的原图由门户/桌面管理；应用不会删除任意门户返回路径，因此不能保证门户后端不保留截图。应用生成的选区临时文件不进入历史；历史只保存文字与译文。OCR 入口文件上限为 20 MiB，大面积高熵选区可能超限，提示后缩小选区即可。

## 实现边界

- `internal/capture/display.go`：显示器目标、虚拟桌面到目标屏幕的裁剪；覆盖横排、竖排、负坐标和缩放格式。
- `internal/capture`：各系统抓屏、解码限制、坐标换算、原图裁剪与临时文件。
- `internal/desktop/selection.go`：框选状态与原生画布。只保存位图、数据与 `ui.Handle`，不跨帧保存元素。
- `internal/bootstrap/capture.go`：固定鼠标显示器，与 `windows.go` 配合隐藏/恢复窗口，创建与关闭同一显示器上的框选窗口；所有窗口操作通过 `mygo.RunOnMain`。
- `internal/bootstrap/display_linux.go`：通过 GTK3 `gtk_window_fullscreen_on_monitor` 将框选层放到目标显示器，兼容 Wayland 下普通窗口不能可靠定位的限制。
- `internal/desktop/app.go`：识别与翻译衔接，context 取消、generation 校验。
- `desktop.Ports.CaptureArea`：测试可替换为固定图片，不需要真实桌面。

截图和 OCR 在后台执行。保存配置、输入新文本、取消或关闭翻译窗口使旧结果失效；晚到的识别结果不会覆盖新输入。

## 自动化与真机验收

```bash
go test ./internal/capture ./internal/desktop
LUMIN_TEST_SCREENSHOTS=/tmp/lumin-screenshots \
  go test ./internal/desktop -run 'TestRenderPages|TestSelectionDragResizeAndCancel' -count=1
```

自动化覆盖画布完整窗口边界、松开即提交、单次完成、右键/Esc、误点重选、原图像素、反向拖动、边界裁剪、窗口缩放、指针取消、Enter/Esc、异步结果隔离、临时文件清理、截图到翻译链路，以及横排、竖排、负坐标、缩放后的显示器裁剪。测试使用固定图片，不能证明系统授权、真实多屏输出或混合 DPI 下的合成器行为。

真机需分别检查：

1. 从托盘、快捷键启动，三个业务窗口都不会出现在快照中；分别测试设置/翻译/识别单独可见、同时可见和全部隐藏。取消后仅恢复之前可见窗口，后台截图不唤起设置。
2. 门户授权允许、拒绝、取消；拒绝后不回退工具，90 秒超时后可重新操作。
3. 框选四个方向、小区域、整图、边界与留白；移动鼠标到每台显示器后截图，确认只出现该屏快照和该屏覆盖层；覆盖横排/竖排、负坐标、不同缩放比例。
4. 使用默认离线 OCR 插件验证中英文混排；切换 OCR 插件并保存，确认截图与图片导入都生效。
5. 拖动期间 Esc、关闭框选窗口、任务超时；不存在遗留覆盖窗口或临时选区图片。
6. 截图翻译后检查编辑器、译文与历史；无翻译服务时给出配置引导。
7. 外部 `POST /ocr_recognize`、`POST /ocr_translate` 带 Bearer 令牌触发相同交互，不返回 OCR 文本。仍需用户授权与框选。

门户协议参考：[XDG Screenshot interface](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Screenshot.html)。

## 0.6.0 独立识别结果

托盘「截图识字」框选后打开文字识别窗口，图片在上、编辑结果在下；「重新识别」不再次框选。托盘「图片识字」选择本地文件走同一视图。「截图翻译」仍打开翻译窗。测试三个业务窗口任意显隐组合，确认截图不包含 Lumin；取消框选只恢复此前可见窗口；关闭识别窗后迟到结果不能弹回。

## 0.10.0 框选与全屏维护

选区在鼠标松开时自动裁剪提交，右键关闭。Lumin 画布只保留截图绘制和输入处理，尺寸/操作提示直接使用 Painter，不占布局空间、不拦截鼠标。比例匹配时图片覆盖完整视口；系统返回不同比例时保留 contain 和原图坐标映射，避免拉伸。

覆盖层以 Frameless/Hidden 创建，绑定关闭回调，定位到已固定的鼠标显示器，全屏后再 Show/Focus，避免先显示有装饰的普通窗口。保留用户已有 GTK 目标显示器全屏逻辑。SelectionView 使用 finished 状态保证所有完成路径最多触发一次；指针取消只清除本次拖动，右键/Esc 则结束截图。

真机需确认没有系统标题栏或顶部空行，顶部边缘文字也可原位框选；多屏时其他屏不出现覆盖层，混合 DPI 下图像与屏幕一致。自动化和交叉构建不替代该验证。

## 0.11.1 截图耗时排查

所有业务窗口已隐藏时不再额外等待 200ms；实际隐藏可见窗口时保留该等待，让合成器移除窗口。首次准备框选位图在工作线程进行，窗口操作仍在 UI 线程。选区临时 PNG 使用 BestSpeed 无损压缩，降低编码延迟；不降低原始像素质量，也不缓存过期屏幕。

从终端启动带阶段日志的版本：

```bash
LUMIN_CAPTURE_TRACE=1 ./build/linux-amd64/lumin
```

先从托盘退出已运行的旧实例，避免单实例机制将请求转交旧进程。日志只含阶段名与耗时，不含图像、文字或路径；默认关闭。

- `screen`：系统取屏完整阶段，Linux 包含门户交互及图片解码。
- `decode-screen`：Linux 门户返回文件的读取/解码，是 screen 的子阶段，不能重复相加。
- `prepare-selection`：框选位图准备。
- `show-overlay`：UI 线程调度、创建和显示窗口，不包含等待用户框选，也不等同于合成器首帧呈现。
- `encode-selection-png`：框选后临时文件编码。
- `ocr`：识别服务耗时，本地插件包含进程启动、模型加载和推理，不包含后续文本翻译。

如延迟主要落在 screen，需进一步检查门户授权和桌面后端；不通过命令工具或绕过权限替代。当前插件仍每次加载模型，常驻模型需要独立的协议与退出/取消设计，本轮没有更改。
